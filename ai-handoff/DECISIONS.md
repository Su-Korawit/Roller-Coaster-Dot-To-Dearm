## 2026-11-06 — ต้องเลือกผู้ให้บริการชำระเงิน (เฟส 3) — ผู้ใช้ต้องตัดสิน
- ยังไม่ต่อระบบจ่ายเงินจริง: มีแค่ interface `api/_voice/payments.js` (createCheckout / parseWebhook / markPaid)
- ตัวเลือก: PromptPay QR + SlipOK (มีในโปรเจกต์แล้ว, ใช้ Firebase Functions), Stripe, Omise
- จนกว่าจะต่อ: `paid=false` ตลอด -> ทดลอง 3 วันเป็น Web Call เท่านั้น, โทรออกไม่ทำงาน (ถูกต้องตามเจตนา)
- ทดสอบโทรออกกับเบอร์ตัวเอง: ตั้ง `paid:true` ใน Firestore ของ uid ตัวเองเอง (ดู docs/voice-secretary.md)

## 2026-11-06 — คิวโทรออก: Vercel endpoint แทน Firebase Scheduler
- Codex แนะนำ Firebase Scheduler; Claude ทำเป็น `POST /api/voice/dial-due` (CRON_SECRET) เพื่อให้ logic อยู่ที่เดียวกับ web-call/webhook
- ข้อแลกเปลี่ยน: Vercel Hobby cron รันได้วันละครั้ง -> ต้องเรียกจาก scheduler ภายนอก หรือ Vercel Pro (ยังไม่ตั้ง cron ใน vercel.json เพื่อไม่ให้ deploy พัง) **ผู้ใช้ตัดสิน**

## 2026-11-06 — ความยินยอมแบบแยก 2 ช่อง (ข้อเสนอจาก ChatGPT ร่าง 004)
- ChatGPT เสนอแยกติ๊ก "ใช้ข้อมูลคุยกับพี่ใจดี" กับ "ใช้เบอร์โทรเพื่อรับสาย (ไม่บังคับ)" — ตรงหลัก PDPA เรื่องความยินยอมแยกวัตถุประสงค์
- ตอนนี้ระบบมีช่องเดียว (consent เดียวครอบ Web Call + โทรออก) ควรแยกก่อนเปิด DIALING_ENABLED **ผู้ใช้/ที่ปรึกษากฎหมายตัดสิน**

## 2026-11-06 — Retell API เปลี่ยน (พบตอนทดสอบจริง)
- `POST /v2/create-web-call` ถูกยกเลิก -> ใช้ `/v3/create-web-call` (ตอบเพิ่ม transport/ice_servers) ส่งต่อให้ SDK แล้ว
- `publish-agent` เดิมถูกยกเลิก -> ใช้ `publish-agent-version` (ต้องระบุเลขเวอร์ชัน)
- `update-agent` ตั้ง max_call_duration_ms=60000 ได้ 422 (ขั้นต่ำ >60s?) จึงปล่อยไว้ที่ 180000 ตามที่ตั้งไว้ — การทดสอบโทรออกจบเองที่ 47 วินาทีเพราะ agent วางสาย
- เบอร์ +13192641997 ยังไม่ผูกกับ agent สำหรับสายเข้า/ออกใน Retell: โทรออกผ่าน API ใช้ override_agent_id จึงทำงานได้; ถ้าต้องการให้สายเข้าตอบด้วยพี่ใจดี ต้องผูกใน dashboard (ผู้ใช้ทำเอง)
