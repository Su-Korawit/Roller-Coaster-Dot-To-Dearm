# Study Room part 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (Native, inline). Steps use checkbox syntax.

**Goal:** Finish the Study Room spec: room tiers 1–3, extra themes, pets, a wardrobe (accessories + outfit hue), the studygram card, the trophy history sheet and friend room visits.

**Architecture:** Everything economic stays server-owned: tiers, themes, pets and accessories are catalog items bought with `buyRoomItem` (unique kinds); the layout (`tier`, `theme`, `petId`, `placed`) is saved only through `saveRoomLayout`, whose rules now know each tier's floor *areas*; the avatar (`users/{uid}.avatar`) is saved only through a new `saveAvatar` callable. The room stays the generic `MapScene` with `cfg.room`: ONE generated map `room` holds a self-contained shell per tier (layers `Shell_t0..t3`), the scene shows only the owned tier's shell and remaps theme tiles at runtime, so buying a tier never switches maps. Pure modules (areas, pet behaviour, card layers, avatar rules) carry the logic; Phaser/React stay thin.

**Tech Stack:** React 19, Zustand, Phaser 3, Firebase Functions v2 + emulator tests, the Part A art pipeline (`scripts/art`, palette lint), Canvas 2D, Web Share API, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-16-study-room-design.md`. Part 1 plan: `docs/superpowers/plans/2026-10-22-study-room.md` (kept `rooms/{uid}.tier|theme|petId`, catalog kinds `tier|theme|pet|outfit|accessory`).

## Scope rulings

- **One map, four shells** (above) instead of four maps: no map switch on purchase, resume points keep working. Camera bounds follow the owned tier's bounding rectangle; unowned space is simply not drawn and not walkable.
- **Tier areas.** Tier footprints (tiles): t0 11×9; t1 14×10; t2 = t1 + lake balcony 6×8 attached to the east wall (door gap in the wall); t3 = t2 + second room 10×9 south of the main room (door gap). `TIER_AREAS[tier]` is a list of rects; a footprint must fit entirely inside ONE area (no straddling a wall). Server copy and client copy share fixtures.
- **Purchases are in order:** `tier_n` needs `tier_{n-1}` owned (`requires` on the catalog row); a layout's tier must be owned. Lowering the tier is allowed only if every placed item still fits (else rejected, nothing is deleted silently).
- **Themes:** `minimal` (free, owned) + `library-wood`, `café`, `night-sky` at 1,500; applied by runtime tile remap (`roomTheme.js`); a missing theme tile falls back to the minimal tile.
- **Pets:** orange cat, black cat, shiba, bunny at 600 Leaves; ONE active pet (`layout.petId`). Behaviour is a pure seeded state machine (wander → groom → sleep on `pet_bed` if placed → sit beside the player during a focus session → heart on tap).
- **Wardrobe:** 8 accessories (2 per slot head/face/neck/back, 250–500 Leaves) drawn as overlay sprites that follow the player's frame; outfit hue is 0–359° applied to the character texture except skin/outline pixels (free). `users/{uid}.avatar = { accessories: {head,face,neck,back}, outfitHue }` is written only by `saveAvatar`. Overlays/hue apply to the player's own avatar and to visitors' view of the owner; other presence avatars keep the plain sprite (cost: friends do not see each other's outfits in the School Hub yet).
- **Studygram card** exactly per spec layout B (1080×1350), composed on a canvas from layers; opt-in toggles for goal faculty and streak; no real name or school. Save image + Web Share (files) with download fallback.
- **Trophy history:** `focusSessions` already readable by their owner; the sheet lists the last 50 sessions (client query `where uid ==`, order by `endedAt` descending, newest first; falls back to an in-memory sort when the index is missing) and offers the card per session. A `trophy_shelf` furniture item (300 Leaves) shows the last 3 trees.
- **Visits:** a friend's room opens read-only from the Social panel ("เยี่ยมห้อง"): the owner's `rooms/{uid}` layout + `users/{uid}.avatar`, presence room `worlds/{ownerUid}/maps/room`. Visitors cannot decorate, buy, start focus or save (the focus seat and the decorate bar are not mounted); a "กลับห้องของฉัน" button returns home. A friend with no room document sees the starter room.
- **Out of scope:** multiple pets, rotation, trading, seasonal events, other-room portals, AI decor (spec).
- **Owner steps (not run by me):** deploy rules → functions (`saveAvatar`, `saveRoomLayout`, `buyRoomItem`) → seed catalog (`seedRoomCatalog.mjs --apply`, creates only missing rows) → upload assets → hosting. Documented in `docs/study-room-ops.md`.

## Global Constraints

- Plain JS/JSX, Soft Pixel tokens only, text ≥ 12 px, Firestore paths only via `src/lib/db.js`, client writes debounced via `syncManager`/`roomSync`; `serviceAccountKey.json` never read; art only through `scripts/art` with the palette lint.
- Economy fields (`leaves`, `roomInventory`, `welcomePack`, `avatar`) are Functions-owned; Leaves are never bought with Coins.
- Prices live in Firestore `roomCatalog`; seed in `src/data/roomCatalogSeed.js`. Tier prices 1,200 / 3,000 / 6,000; themes 1,500; pets 600.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Layout integrity across tiers:** an item placed in an area the tier does not own, straddling a wall between areas, a tier downgrade that strands items, a `tier` the user does not own, a theme/pet not owned, parallel `saveRoomLayout` + `buyRoomItem`.
2. **Purchases and avatar:** `tier_2` before `tier_1`, buying a unique item twice in parallel, `saveAvatar` with an accessory not owned / wrong slot / unknown id / `outfitHue` out of range or non-integer, `avatar` written by a client directly (rules).
3. **Studygram card:** no name/school/email on the image, empty room or no items owned (nothing drawn, still a valid card), long durations (formatting ≥ 100 min), canvas unavailable, share unsupported/cancelled, very fast double tap (one file).
4. **Visits:** a visitor cannot write the owner's room, edit, buy or focus; visiting oneself; a friend with no/old room document; leaving restores the visitor's own room; presence cleanup.
5. **Scene robustness:** theme tile missing → fallback, tier shell layer missing in an old cached map, pet stuck on furniture/outside the floor, pet and accessories after a tier change, hue recolor leaves transparent pixels alone, reduced motion.
