# TCAS Plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (Native, inline). Steps use checkbox syntax.

**Goal:** A Plan sheet (hotbar slot 3) where the student's chosen programs become a round-by-round plan with an auto checklist, a "next thing to do" card from the TCAS calendar, round-3 ranking, and per-subject focus-hour goals that start a focus session in one tap.

**Architecture:** Extend the existing `usePlansStore` entries (versioned, backward compatible) instead of forking a new model; all derivation (checklist, subject aggregation, goals, next milestone, round status) is pure in `src/utils/planDerive.js`; the sheet is thin UI over it. The only server change is `focusBySubject` (Functions-owned) incremented by `endFocus` for sessions started with a valid `subjectKey`.

**Tech Stack:** React 19, Zustand (persist), `@hello-pangea/dnd`, Firebase Functions + emulator, Vitest 4.

**Spec:** `docs/superpowers/specs/2026-10-16-tcas-plan-design.md` (mockup `mockups/plan.html`, the three phone screens: add flow, plan overview, subjects).

## Scope rulings

- **Entry snapshot:** each entry also stores `scores: [{ key, label, weight }]` and `minGpax` copied from the chosen project when it is added. The spec's model has no scores, but subject aggregation, chips and the checklist all need them and the Open House index is a per-building file that must not be re-fetched for every plan row. `v: 2` marks the new shape.
- **Open House is not built yet:** the add flow is a `RoundPickerSheet` driven by a `usePlanUiStore.openAdd(program)` call (program = `{ universityId, universityName, programId, programName, buildingId, rounds: [{ round, projects[] }] }`); the Open House popup will call it. Until then nothing in the UI calls it, and it is covered by unit/component tests.
- **Slot cap unchanged:** total entries ≤ `FREE_PLAN_SLOTS + extraPlanSlots()`; at the cap `addFromProgram` returns `{ ok: false, reason: 'cap' }` and the picker shows the existing Unlock path text.
- **No invented dates:** the milestone card only uses `tcasEvents` (admin) or the built-in TCAS70 calendar rows, which are tagged here with `round` / `kind` / `examKeys`.
- **Guide:** the guide's Plan step stays unavailable until Open House ships (it needs a program to add).

## Global Constraints

- Plain JS/JSX, Tailwind Soft Pixel tokens only, text ≥ 12 px (legacy ratchet), Firestore paths via `src/lib/db.js`, plan sync through the existing `syncSelectToFirestore` path.
- `users/{uid}.focusBySubject.{key}` (ms) is Functions-owned (rules deny client writes/create like `leaves`). Valid subject keys: `tgat`, `tgat1-3`, `tpat1-5`, `tpat11`, `tpat13`, `tpat21`, `a_lv_61…a_lv_89`.
- Default goal hours per subject `20 + round5(60 × maxWeight / 100)`; round 3 rank 1–10, unique.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Old data:** entries saved before this change (no `round`, `programId`, `checklist`) in `localStorage`, in `users/{uid}.profile.plans`, and the `legacy` entry synthesised by `readProfile` must load, sync back and keep working in onboarding/profile.
2. **Rank integrity:** adding, removing, moving rounds and reordering must never leave duplicate or gapped ranks in round 3 or more than 10.
3. **Subject focus abuse:** `startFocus` with a junk/oversized/proto-polluting `subjectKey`, ending twice, practice sessions, and withered sessions must never write a bad key or count a session twice.
4. **Guest and merge:** guest plans mark the guest-dirty flag and merge at login without duplicates; the cap holds for guests.
5. **Dates:** a missing calendar yields "no date", never a wrong one; past events are never "next"; today counts as 0 days.
