# OS Shell — Plan

**Goal:** Redesign the app site as a device-like OS: Login with Google → set/enter a device passcode → Home (icon grid, pages, clock, wallpaper) → apps open in a window. All existing features stay hidden; only OS apps are shown. **Settings app is out of scope for now.**

**Architecture:** New `src/os/` layer mounted at `/` on the app site (old WelcomePage moves to `/welcome`). One state machine in `OsShell`: loading → login → consent → set/unlock passcode → home. App registry (`src/os/apps.js`) is the single place the owner adds apps later. `useOsStore` (persist `rc-os-store`) holds wallpaper + installed apps.

**Decisions (builder's calls, not user-approved):**
- Passcode = 6-digit PIN, per device. SHA-256 (uid-salted) in localStorage `rc-os-pass-<uid>`. Not synced to Firestore (a device passcode, like a real phone). Forgot → clear + sign out → Google sign-in again.
- Unlock state is in memory only: a refresh locks the screen.
- Layout: phone/tablet = status bar on top, clock top-right; desktop = taskbar at the bottom, clock bottom-right (as in the sketch).
- Long-press (or right-click) an icon → app details; long-press empty space → wallpaper picker.
- Help button ("พี่ช่วยเหลือ") opens the existing AI secretary (VoiceSecretaryPanel) in a window.
- Store: search, banner, installable-app grid, empty state for now, "create your own app" teaser (disabled).
